# Day 12 demo — Персонализация ассистента (video cheat sheet)

Короткая шпаргалка для записи видео на 3–5 минут. Полная документация — в
[README.md](README.md), раздел «День 12 — Персонализация ассистента».

## Подготовка

```bash
uvicorn app.main:app --reload --port 8000
pytest tests/test_day12.py -q
```

Открыть UI <http://127.0.0.1:8000> и вкладку
**«День 12 — Персонализация ассистента»**.

## Ключевая идея (проговорить в начале)

Профиль — это **не** сообщение в истории. Он хранится отдельно
(`data/day12_user_profile.json`) и backend автоматически добавляет его к
**каждому** запросу. Пользователь не повторяет предпочтения в сообщении.

```text
System / application rules   ← высший приоритет
        +
USER PROFILE                 ← этот день
        +
Memory / Context             ← День 11
        +
Conversation history
        +
Current user message
```

## Сценарий записи

1. **Открыть вкладку «День 12».** Показать:
   - схему приоритетов вверху;
   - блок «Активный профиль» с чипами активных предпочтений;
   - точные инструкции, которые получает модель
     (`USER PROFILE (presentation preferences) ...`).
2. Нажать готовый профиль **«Краткий»** → показать, что редактор и инструкции
   обновились, и что backend сохранил профиль.
3. **Сравнение на одном вопросе.** В блоке «Сравнение профилей» оставить
   подготовленный вопрос (в нём нет инструкций по стилю):
   > Помоги Антону разобраться: как устроен индекс в базе данных
   > и почему он ускоряет поиск?
   Нажать **«Сравнить профили»** → рядом три карточки: Краткий / Подробный /
   Технический. Проговорить: текст вопроса одинаковый, память отключена,
   разница — **только из-за профиля**.
4. **Автоматическое применение.** В чате внизу отправить тот же вопрос
   (или «Что такое HTTP?») при сохранённом профиле `concise` → короткий ответ.
   Затем применить профиль **«Подробный»** и отправить **тот же самый** вопрос
   → подробный структурированный ответ. Обратить внимание: сообщение не
   менялось, изменился только профиль.
5. **Совместимость с памятью Дня 11.** Включить `Memory Layers` и
   `MemoryClassifier`, отправить:
   > Меня зовут Антон, пишу на Python. Сейчас делаем сервис бронирования,
   > PostgreSQL нельзя.
   Затем задать вопрос. Показать панель `MEMORY (День 11)` и `Context Builder`:
   в `included_layers` видны `system`, `personalization`, `long_term`,
   `working`, `short_term`, `current_user` — профиль и память работают вместе.
6. **Приоритет system instructions.** Раскрыть инструкции профиля и показать
   последнюю строку: профиль — «presentation preferences only», системные
   правила всегда важнее.

## Свободные инструкции — custom_instructions

Поле **«Свои инструкции»** в редакторе профиля принимает произвольный текст.
Он сохраняется вместе с профилем, загружается обратно и автоматически
добавляется backend'ом в блок персонализации каждого запроса — повторять
инструкцию в сообщении не нужно.

### Сценарий 1 — стиль без указания стиля в вопросе

1. В редакторе в поле **«Свои инструкции»** вписать:
   > Отвечай как быдло.
2. Нажать **«Сохранить профиль»** и проверить блок «Инструкции, которые
   получает модель»: появится секция `Additional user instructions:`.
3. В чате отправить обычный вопрос (в нём нет никаких указаний по стилю):
   > Объясни, зачем программисту нужны автоматические тесты.
4. Ответ должен сменить стиль, хотя в самом вопросе стиль не задавался.

### Сценарий 2 — транслит тем же вопросом

1. Заменить содержимое поля **«Свои инструкции»** на:
   > Пиши только транслитом.
2. Нажать **«Сохранить профиль»**.
3. Отправить тот же самый вопрос:
   > Объясни, зачем программисту нужны автоматические тесты.
4. Ответ должен прийти транслитом — снова без изменения текста вопроса.

Тесты механизма: `tests/test_day12.py` проверяют сохранение поля в профиле и
его попадание в формируемые personalization instructions.

7. Быстро показать код (по 5–10 секунд):
   - `app/schemas/day12.py` — структура `UserProfile`;
   - `app/services/day12/profile.py` — `build_personalization_instructions`,
     пресеты и `ProfileStore`;
   - `app/services/day12/service.py` — применение профиля через Day 11;
   - `app/services/day11/service.py` — `_build_context` (порядок слоёв).

## Что важно проговорить

- Профиль отделён от истории сообщений и от памяти.
- Frontend редактирует **структурированный** профиль; LLM-инструкции строит
  только backend (единое место).
- Профиль определяет только «как» отвечать и не может переопределить
  системные правила.
- Один и тот же вопрос даёт разное поведение при разных профилях.
- Персонализация работает поверх памяти Дня 11, не заменяя её.
