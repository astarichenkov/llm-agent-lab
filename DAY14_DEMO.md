# Day 14 demo — Инварианты и ограничения состояния (video cheat sheet)

Короткая шпаргалка для записи видео на 5–7 минут. Полная документация — в
[README.md](README.md), раздел «День 14 — Инварианты и ограничения состояния».

## Подготовка

```bash
uvicorn app.main:app --reload --port 8000
pytest tests/test_day14.py -q
```

Открыть UI <http://127.0.0.1:8000> и вкладку **«День 14 — Инварианты»**.

## Ключевая идея (проговорить в начале)

Инварианты — это **обязательные правила**, которые ассистент не имеет права
нарушать. Они:

* хранятся **отдельно** от истории диалога (`data/day14_invariants.json`);
* передаются модели отдельным блоком **`ACTIVE INVARIANTS`**;
* проверяются на конфликт **детерминированно в коде** (не формулировкой LLM).

```text
Task State (День 13)      Invariants (День 14)        Conversation
  phase                     architecture              user:  ...
  current_step        +     technical decisions  +    assistant: ...
  expected_action           stack / business rules
```

## Активные инварианты

| Категория | Правило |
|-----------|---------|
| Architecture | Backend должен оставаться монолитным FastAPI-приложением |
| Technical decision | Использовать PostgreSQL |
| Stack | Backend реализуется на Python |
| Business rule | Удаление пользовательских данных требует явного подтверждения пользователя |

## Сценарий записи

1. **Открыть Day 14.** Показать блок **ACTIVE INVARIANTS**: 4 правила с
   категориями. Отдельно отметить, что это **не сообщения** в чате — рядом
   есть блок «История диалога (raw)», где инвариантов нет.

2. **Разрешённый запрос (нет конфликта).** Отправить:
   > Добавь endpoint /health в существующий FastAPI backend.
   Показать результат **РАЗРЕШЕНО**, нормальный ответ агента, зелёный статус.
   Раскрыть «Показать ACTIVE INVARIANTS, отправленные модели» — тот самый блок
   ушёл в запрос к DeepSeek.

3. **Конфликт с одним инвариантом.** Отправить:
   > Перепиши backend на Go.
   Показать **КОНФЛИКТ**, карточку `Stack — stack` с правилом
   «Backend реализуется на Python» и совпадением `"go"`. В ответе — явное
   объяснение, почему запрос отклонён.

4. **Несколько конфликтов.** Отправить:
   > Перепиши backend на Go, разбей его на микросервисы и замени PostgreSQL на MongoDB.
   Показать три карточки конфликтов: `Architecture`, `Technical decision`
   (`database`), `Stack`. Все три инварианта названы в одном отказе.

5. **Business rule.** Отправить:
   > Удаляй аккаунт пользователя сразу без подтверждения.
   Показать конфликт `Business rule — business_rule` и объяснение отказа.

6. **Очистка истории.** Нажать **«Очистить историю»**. Показать, что история
   диалога очистилась, а **блок ACTIVE INVARIANTS остался** — сущности
   независимы.

7. **Код (по 5–10 секунд):**
   - `app/schemas/day14.py` — `Invariant`, `InvariantConflict`;
   - `app/services/day14/invariants.py` — `DEFAULT_INVARIANTS`,
     `detect_conflicts`, `build_invariants_block`, `build_refusal`;
   - `app/services/day14/service.py` — `build_context`, `chat`
     (проверка → отказ/ответ);
   - `app/services/day14/store.py` — отдельное хранение инвариантов.

## Что важно проговорить

- Инварианты **отделены** и от `messages`, и от Task State Дня 13.
- При конфликте ассистент **не соглашается**: отказ формируется кодом.
- Пользователь видит, **что попросил → какой invariant нарушен → почему отказ**.
- Разрешённые запросы работают как обычно — инварианты не блокируют всё.
- LLM не выводит скрытые chain-of-thought: явен только результат проверки.
